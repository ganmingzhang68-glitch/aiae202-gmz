咱们微专业一共四门课：前两门是基础，后两门同期开设、各自独立，可以一起上，也可以只上一门：

前两门课你们学会了写 Python、跑数据。AIAE201 补的是工程流程那一层：命令行、Git、测试、部署。这门课讲另一件事：让大语言模型不只是回答问题，而是替人把事做了——调工具、查资料、走流程、留记录。两门课互不为前提：这门课用到的命令行和 Git 只有最基本的几条，今天就会带着过一遍；结课作品也是一个独立的智能体产品，不依赖另一门课的项目。

4–6 min

为什么现在要学 Agent 开发

过去两年大家用大模型的方式，基本是"问一句、答一句"：模型只会生成文本，做不了任何事。真正有用的系统要能查数据库、调 API、发消息、跑代码——这就是 AI 智能体（Agent）：以大语言模型为推理引擎，配上工具和知识，替用户在真实世界里采取行动。

你们可能会问：不就是给模型加几个函数吗，有什么好学十六周的？

先说结论：加函数只是第一天的事。难的是后面——模型什么时候该调工具、调错了怎么办、多步任务怎么规划、几个智能体怎么协作、有风险的动作谁来批、上线之后怎么知道它在干什么。这些才是"Agent 产品"和"能跑的 demo"之间的距离，也是这门课要练的。

6–7 min

同一句话，这门课站到另一边

用 AI 编程代理写代码的人，都得做到九个字：看得懂、拦得住、接得住——坐在屏幕前，审 AI 敲的每一条命令。同期的 AIAE201 讲的就是这一边。

这门课站到另一边：你来设计那个替人干活的 AI。你的智能体也会调用工具、也会执行动作，而屏幕前的用户，未必读得懂它在干什么。所以用户对 AI 的要求，这门课要变成你对自己作品的要求：

  • 每一步为什么调这个工具、传这些参数，用户看得懂——要有可观测性；
  • 有风险的动作，拦得住——要有人工审批和防护；
  • 模型犯错、卡住，系统接得住——要有回退、评估和记录。

这三条贯穿十六周，每一课都会回到它。

7–9 min

结课的时候，你要交出什么

一个你自己专业里的智能体产品：一个能在浏览器里访问的简单界面（聊天框或表单就够），后面接一个能替用户干活的智能体，用容器打包部署。题目自己选择，比如：

  • 实验数据助手：读取仓库里的数据表，按用户要求算指标、画图、写报告
  • 文献调研智能体：检索本地论文库，规划阅读路线，生成带引用的综述
  • 仿真任务管家：按自然语言指令提交批量仿真、查进度、汇总结果

而且要具备生产级智能体的完整要素：工具 → 检索 → 记忆 → 规划 → 人工审批 → 可观测性 → 评估 → 部署。仓库里每一环都要留下记录——工具设计、提示词版本、评估集、链路日志、部署记录，一样不缺。

第 7 周立项选题，中间有几个检查点，第 16 周当着全班演示答辩。同时在上 AIAE201 的同学，可以把两门课的作品合成一个系统，但这不是要求。

9–12 min

比"做出来"更重要的事

说实话，让模型调几个工具、凑一个能演示的智能体，现在让 AI 跑 1–2 小时也能凑合出来。这门课真正要练的是下面三条，也是考核的重点：

  • 拿到一段智能体的运行记录——它收到的消息、发起的工具调用、拿到的结果、最后的回答——你能逐条讲清楚它为什么这么做，并指出哪一步不对劲；
  • 智能体答错了、循环了、把工具用歪了，你能找到原因：是提示词、是工具描述、是上下文，还是模型本身；
  • 系统里任何一个工具、任何一段提示词，你都说得清它是干什么的、为什么这么写、有什么风险。

一句话：智能体可以替用户干活，但不能替你负责。

32–33 min

从最底下这层开始

AI 智能体到底是什么

刚才那个旅行助手，就是一个最小的智能体。接下来我假设大家只用过聊天框，从头讲。一句话的定义：

AI 智能体是让大语言模型真正做事的系统——
给它工具和知识，让它作用于外部世界，而不只是回复提示词。

把这句话拆开，有三个词要抓住：系统、大语言模型、做事。下面三页一个一个说。

33–34 min

它是一个系统，不是一个模型

每个智能体的核心都有三部分，拿旅行预订智能体举例：

部件是什么旅行智能体里
环境智能体工作的空间预订平台本身
传感器它怎么读取环境的当前状态查酒店空房、查机票价格
执行器它怎么采取行动订房、发确认信息、取消预订

在代码里，传感器和执行器长得一样：都是工具——一个被暴露给模型的 Python 函数。区别在于后果：查是只读的，订是有副作用的。这个区别以后每周都要用，今天先记住。

34–36 min

大语言模型只会生成文本，"做事"靠的是系统

智能体在 LLM 出现之前就有了。LLM 带来的是：能理解自然语言、结合上下文推理、把一句含糊的请求变成具体的行动计划。但它自己动不了手——模型的输出永远是一段文本。

"做事"是这样发生的：模型输出一段特殊格式的文本，说"我要调用 get_destinations，参数是……"；系统真的去执行那个函数，把结果作为一条消息回传给模型；模型再决定是继续调工具还是给出答案。这一来一回就叫工具调用循环，是所有智能体框架的核心。

所以还有两样东西决定了智能体能做什么：

  • 可用的工具——取决于它所处的环境，以及你选择接了什么进去。旅行智能体也许能查航班，但不能改客户记录；
  • 记忆与知识——短期记忆是当前这段对话，长期记忆是客户数据库、过往交互。旅行智能体可能"记得"你偏好靠窗座位。

36–38 min

智能体有几种，一个例子贯穿

类型它做什么旅行智能体示例
简单反射型按写死的规则行事，没有记忆也不规划看到投诉邮件 → 转给客服，仅此而已

今天演示的是目标驱动型；第 8 周做分层式和多智能体。这张表不要求背，要求的是看到一个系统，能说出它是哪一种、缺哪一种能力。

38–39 min

能用智能体，不代表就该用

智能体比一次普通的模型调用贵、慢、也更难预测。只有下面这些场景才值得：

  • 开放式问题——解决问题的步骤无法预先写死，需要模型动态地找路径；
  • 多步骤流程——任务需要跨多轮使用工具，而不只是一次查询或一次生成；
  • 随时间改进——希望系统能根据用户反馈或环境信号变得更聪明。

反过来：步骤固定、能写成 if-else 的，就写 if-else；只要一次总结、一次翻译的，直接调模型。把不该用智能体的地方硬做成智能体，是结课项目里最常见的失分点之一。第 6 周"可信赖的智能体"会专门讲什么时候不该用。

39–41 min

一个智能体由什么组成

构建智能体的第一件事，是定义它能做什么——它的工具、动作和行为。本课程里，一个智能体由三样东西组成：

  • 模型：任意暴露了 OpenAI 兼容接口、支持工具调用的模型——DeepSeek、OpenAI、MiniMax、本地 Ollama 或 vLLM，改三个环境变量就能换；
  • 知识：来自你自己数据源的资料，第 5 周用向量库把它接进来；
  • 工具：任何被暴露为工具的 Python 函数，或者一个 MCP 服务器（第 11 周）。

光有这三样还不够。智能体要跨很多步骤行动，你没法每一步都手工写提示词，所以需要智能体式模式——一套可复用的提示与编排策略；而框架把这些模式做成了现成的积木。本课程用的是 LangChain 1.x（智能体）和 LangGraph 1.x（工作流），两者是同一个技术栈的两层。

$ python3 -m venv .venv && source .venv/bin/activate $ pip install -r requirements.txt $ cp .env.example .env # 然后打开 .env 填四个值

.env 已经写进 .gitignore，所以你的 key 只会留在本机——这也是它不能出现在任何 notebook 里的原因。

$ python scripts/check_endpoint.py Endpoint: https://api.deepseek.com/v1 Model: deepseek-v4-pro capability result used by lessons chat PASS all lessons tools PASS 01, 03-05, 07-13, 16-18 (create_agent needs tool calling) structured PASS 03, 07, 08 (structured output forces a tool call) vision PASS 10, 15 — optional Ready: this endpoint supports everything the course requires.

51–55 min

第一个 notebook，一共四段

# 1 模型客户端：读 .env，换服务商只改这三个变量 llm = ChatOpenAI(model=..., base_url=..., api_key=..., extra_body=...) # 2 工具：一个普通函数，docstring 就是模型看到的说明 @tool def get_destinations() -> list[str]: """获取热门度假目的地列表。""" # 3 智能体：模型 + 工具 + 指令，跑工具调用循环 agent = create_agent(llm, tools=[get_destinations], system_prompt="你是一名热心的旅行顾问……") result = agent.invoke({"messages": [{"role": "user", "content": "..."}]}) # 4 流式：一个词一个词地拿 async for token, metadata in agent.astream(..., stream_mode="messages"): ...

今天不要求写出来，要求的是：给你这四段，你能指出哪一行决定了模型能用什么工具、哪一行决定了它的角色、结果里的四条消息各是谁发的。

55–57 min

读任何一条工具调用，问四个问题

拿条真家伙练一下——这是智能体消息历史里完全可能出现的一条：

AIMessage tool_calls=[{"name": "send_email", "args": {"to": "all@company.com", "subject": "退款已批准", "body": "..."}}]
  1. 它调了什么工具？send_email，发邮件。
  2. 参数从哪来的？收件人是全公司——用户说过这个吗，还是模型自己编的？
  3. 模型凭什么这么判断？回头看系统提示词和工具的 docstring：有没有告诉它"退款要先确认"？
  4. 出错了怎么办，可逆吗？邮件发出去就收不回来。稳妥做法：这类工具执行前必须停下来等人批（第 4、6 周）。

这四问，以后每周批注智能体运行记录时都用，建议抄进笔记。

57–58 min

看到这几样，先停一下

  • 有副作用的工具——写库、发信、付款、删文件——没有人工审批就直接执行；
  • 代码或 notebook 里出现 sk- 开头的字符串——API key 写死进去了；
  • 一个 run_shell(cmd) 之类的工具，让模型执行任意命令；
  • 工具返回的内容里夹着"忽略之前的指令……"——提示注入，模型可能照做；
  • 回答里出现了工具根本没返回过的数据——它在编，"几乎正确"最难发现；
  • 工具调用循环没有步数上限——模型卡住时会一直调、一直烧钱。

不是说这些永远不能出现，而是：出现它们的时候，你必须清楚地知道自己在批准什么。完整的清单在第 6 课讲义里，每周批注时对照。

74–80 min

逐条讲下来

  • 标记 1——最要命的一处：工具返回的十个城市里根本没有三亚，也没有一个海滨城市。模型调了工具、拿了结果，然后把结果扔在一边，凭自己的知识答了。正确的回答是"可选目的地里没有海滩"，它却给了一个列表外的推荐，还让人放心下单。这就是"几乎正确"——不去核对工具结果的人根本发现不了。
  • 标记 2——"本周最低机票约 ¥880 起"：没有任何工具查过机票，这个数字是编的（同一段代码连跑三次，报的价各不相同）。回答里出现工具没返回过的数据，就该停。
  • 标记 3——API key 写死在代码里。这段代码一提交，key 就进了仓库历史，删都删不干净。

修法在系统提示词和环境变量里，不在模型里：

system_prompt="……只推荐 get_destinations 返回的目的地。" "不要报价格或余票，告诉用户这些需要到预订渠道核实。" api_key=os.environ["LLM_API_KEY"]

改完再跑一遍、再读一遍四条消息——实测改完后最后一条变成"当前的热门目的地列表中暂时没有暖和的海滩可选"。这个"改、跑、读"的循环，就是这门课每周都在做的事。
